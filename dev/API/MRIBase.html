MRIBase ​

MRIBase defines the data types that the other packages build on: raw data organized like an ISMRMRD file (RawAcquisitionData), k-space data prepared for reconstruction (AcquisitionData) and k-space trajectories (Trajectory), together with functions to access and convert them. MRIBase does not depend on other packages of this repository. MRIReco re-exports it, so using MRIReco makes all names on this page available.

Flags ​

The guide Select and Prepare Profiles shows how to use the flags. Each name in FLAGS is also exported as a UInt64 bit mask, for example ACQ_IS_NOISE_MEASUREMENT, for working with head.flags directly.

MRIBase.FLAGS Constant
julia
FLAGS::Dict{String, Int}

A dictionary mapping string keys (representing flag names) to bit positions, counting from 1 for the least significant bit. Flags are used to indicate specific attributes of the corresponding Profile. Example flag names include "ACQ_FIRST_IN_ENCODE_STEP1", "ACQ_LAST_IN_SLICE", etc.

source
MRIBase.create_flag_bitmask Method
julia
create_flag_bitmask(flag::AbstractString) -> UInt64
create_flag_bitmask(flag::Integer) -> UInt64

Creates a bitmask for the given flag.

  • If the flag is a string, its integer value is looked up in FLAGS.

  • If the flag is an integer, it must be positive. The bitmask is created by left-shifting 1 to the corresponding bit position.

Arguments

  • flag: A string representing the flag name or a positive integer.

Returns

  • A UInt64 bitmask where only the bit corresponding to the flag is set.

Throws

  • KeyError if the string flag is not found in FLAGS.

  • DomainError if the integer flag is not positive.

Example

julia
create_flag_bitmask("ACQ_FIRST_IN_ENCODE_STEP1")  # 0x0000000000000001
create_flag_bitmask(2)                           # 0x0000000000000002

The guide Create AcquisitionData from Arrays shows how to create it from arrays, and Data Model explains its fields.

MRIBase.AcquisitionData Type

struct describing MRI acquisition data with floating point precision T and D encoding dimensions (2 or 3).

Fields

  • sequenceInfo::Dict{Symbol,Any} - additional information on the pulse sequence

  • traj::Vector{Trajectory{T}} - trajectories for each echo/contrast

  • kdata::Array{Matrix{Complex{T}},3} - each matrix contains data for one trajectory (1. dim k-space nodes, 2. dim coils) the outer dims describe: 1. dim echoes, 2. dim slices, 3. dim repetitions

  • subsampleIndices::Vector{Vector{Int64}} - indices sampled for each echo/contrast

  • encodingSize::NTuple{D,Int64} - size of the underlying image matrix

  • fov::NTuple{3,Float64} - field of view in mm

source
MRIBase.AcquisitionData Method
julia
AcquisitionData(kspace::Array{Complex{T},6}; enc2D=false)

Returns an AcquisitionData struct created from a zero-filled kspace with 6 dimensions : [x,y,z or slices,channels,echoes,repetitions]

Different undersampling patterns can be handled only along the echo dimension.

This method assumes the data to correspond to a single volume encoded with a 3d Cartesian sequence or in 2D multi-slice with keyword enc2D = true

Keywords :

  • enc2D=false: if true, the 3rd dimension is supposed to store the 2D slices

Notes :

  • The current implementation is using the same subsampling mask for all NR and Slices (only echoes can be different)

Trajectories ​

The guide Create a Trajectory shows how to create trajectories.

MRIBase.Trajectory Type

struct describing a trajectory with element type T

Fields

  • name::String - name of the trajectory

  • nodes::Matrix{T} - sampling locations in k-space. (1.dim <-> dimensions of k-space, 2. dim <-> sampling points)

  • times::Vector{T} - sampling times in s

  • TE::T - echo time in s

  • AQ::T - readout duration in s (per profile)

  • numProfiles::Int64 - number of profiles

  • numSamplingPerProfile::Int64 - number of sampling points per profile

  • numSlices::Int64 - number of slices (for 3d trajectories)

  • cartesian::Bool - true if sampling points lie on a cartesian grid

  • circular::Bool - true if kspace is covered in a circular domain

source
MRIBase.Trajectory Method
julia
Trajectory(nodes::AbstractMatrix{T}, numProfiles::Int64, numSamplingPerProfile;
           times=nothing, TE=0.0, AQ=1.e-3, numSlices::Int64=1,
           cartesian::Bool=false, circular::Bool=false) where T <: AbstractFloat

creates a trajectory named "Custom" from the k-space positions nodes, a Matrix{T} with one row per dimension and one column per sample, ordered profile by profile and, in a stacked 3d trajectory, partition by partition. Without times, the samples of each profile are spread over the readout duration AQ, starting at TE.

Arguments

  • nodes::Matrix{T} - k-space positions between -0.5 and 0.5 (other matrix types, such as a transpose, have to be converted with Matrix first)

  • numProfiles::Int64 - number of profiles per partition

  • numSamplingPerProfile - number of sampling points per profile

  • (times=nothing) - sampling times in s, a Vector{T} with one time per node

  • (TE=0.0) - echo time in s

  • (AQ=1.e-3) - readout duration in s (per profile)

  • (numSlices::Int64=1) - number of partitions (slices) of a stacked 3d trajectory

  • (cartesian::Bool=false) - true if the nodes lie on the cartesian grid in the order of CartesianTrajectory (CartesianTrajectory3D in 3d): without a correction map, the reconstruction and the default simulation then use FFTs, which ignore the nodes

  • (circular::Bool=false) - true if the nodes cover a circular region of k-space, as in radial and spiral trajectories: the reconstructions "direct", "standard" and "multiCoil" then set the image outside a circle (a sphere in 3d) whose diameter is the largest side of the image to zero, and with a correction map, the encoding operator ignores the image outside it
