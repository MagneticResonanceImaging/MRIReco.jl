MRISimulation ​

MRISimulation simulates MRI data from images, including coil sensitivities, field inhomogeneities and relaxation. MRISimulation depends on MRIBase and MRIOperators. It has to be loaded with using MRISimulation, because MRIReco does not depend on it. The guide Simulate k-Space Data shows how to use these functions.

This method is meant to save the result of simulation(image, simParams) in the file filename, or to load it from there if force=false and the file exists. The functions it calls for this belong to MRIFiles, which MRISimulation does not depend on, so it throws an UndefVarError, also after using MRIFiles: right away if force=false and the file exists, otherwise after the simulation.

source
julia
simulation(tr::Trajectory{T}, image::Array{Complex{T}}, correctionMap::Array{Complex{T}} = Complex{T}[];
           opName = "fast", senseMaps = [], verbose = true, kargs...) where T<:AbstractFloat

simulates the k-space data of image on the trajectory tr with the operator that fourierEncodingOp builds for opName with echoImage=false, so the sampling times count from the excitation; slice by slice for a two-dimensional trajectory and at once for a three-dimensional one. Returns an AcquisitionData.

Arguments

  • tr::Trajectory - two- or three-dimensional trajectory

  • image::Array{Complex{T}} - image to be transformed, with two or three dimensions

  • (correctionMap) - complex correction map of the size of image with the relaxation rate R₂* in 1/s as its real part and the off-resonance frequency in rad/s as its imaginary part

  • (opName="fast") - "fast" or "explicit"; Simulate k-Space Data lists the cases in which only "explicit" works, such as a three-dimensional trajectory with a correction map that is not zero

  • (senseMaps=[]) - coil sensitivities of size (nx, ny, nz, number of coils), with nz = 1 for a two-dimensional image; without them, one coil with sensitivity 1 in double precision. For a Float32 trajectory, give them in single precision, for one coil ones(ComplexF32, nx, ny, nz, 1)

  • (verbose=true) - shows a progress bar

  • (kargs) - the options alpha, m, K and method of the approximation that FieldmapNFFTOp uses for a correction map that is not zero; other keyword arguments are ignored

julia
simulation_fast(tr::Trajectory{T}, image::Matrix, correctionMap::Array{Complex{T}} = Complex{T}[];
                alpha::Float64 = 1.75, m::Float64 = 4.0, K::Int64 = 16, method = "nfft",
                senseMaps = [], kargs...) where T

simulates the k-space data of image on the trajectory tr with the operator that fourierEncodingOp builds for "fast" with echoImage=false: an FFT or an NFFT, or a FieldmapNFFTOp for a correction map that is not zero. Returns an AcquisitionData.

Arguments

  • tr::Trajectory - two-dimensional trajectory

  • image::Matrix - image to be transformed

  • (correctionMap) - complex correction map of the size of image with the relaxation rate R₂* in 1/s as its real part and the off-resonance frequency in rad/s as its imaginary part

  • (alpha, m, K, method) - options of the approximation that FieldmapNFFTOp uses for a correction map that is not zero; without such a map, they have no effect

  • (senseMaps=[]) - coil sensitivities of size (size(image)..., 1, number of coils); without them, one coil with sensitivity 1 in double precision. For a Float32 trajectory, give them in single precision, for one coil ones(ComplexF32, size(image)..., 1, 1)

  • (kargs) - passed on to simulation with a trajectory, for example verbose=false to turn off the progress bar

Sequences ​

MRISimulation.MESequence Type

General Multi-Echo sequence with variable flip angles and TR.

The phase of the excitation pulse has a phase of -90° in order to fulfill CPMG conditions.

For simplicity instantaneous pulses are assumed.

The echoes appear at the times T_echo after the excitation pulse.

Fields

  • excitationAngle::Float64 - flip angle of the excitation pulse

  • refocusingAngles :: Vector{Float64} - flip angles of the refocusing pulses

  • T_rf::Vector{Float64} - times of the refocusing pulses relative to the excitation pulse

  • T_echo:: Vector{Float64} - echo times relative to the excitation pulse

MRISimulation.echoAmplitudes Function
julia
echoAmplitudes(seq::MESequence, R1::AbstractFloat, R2::AbstractFloat, numStates=nothing)

calculates echo amplitudes for a given MESequence and given relaxation Rates R1, R2. Calculations are performed using the extended phase graph method. For simplicity instantaneous pulses are assumed. If numStates=nothing all dephasing states will be taken into account

Arguments

  • seq::MESequence - pulse sequence

  • R1::AbstractFloat - R1 value to use (1/T1)

  • R2::AbstractFloat - R2 value to use (1/T2)

  • numStates=nothing - number of dephasing states to consider
